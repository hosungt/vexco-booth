1. 그래도 막막해하시면: **학교급 → 단원 → 활동 취향**(문제 풀이형 / 게임형).

### ③-3. 파일 만들기

```bash
mkdir -p /c/dev/vexco-booth/workspace/<이름>
cp /c/dev/vexco-booth/templates/quiz.html /c/dev/vexco-booth/workspace/<이름>/index.html
```

(쉘에 맞는 파일로 바꿔 복사한다.)

그다음 **복사본에서 `<script type="application/json" id="config">` 와 바로 다음 `</script>`
사이의 JSON 블록만** Edit 으로 교체한다.

- **엔진(CSS/JS)·HTML 구조는 절대 수정하지 않는다.** 바꾸는 건 JSON 데이터뿐이다.
- 필드·타입·제약은 **각 템플릿 상단 주석의 CONFIG 스키마**가 정본이다. 헷갈리면 그 주석을 읽는다.
- **`</` 이스케이프**: CONFIG 문자열 값에 `</` 가 들어가면 반드시 `<\/` 로 적는다
  (예: `x<sup>2<\/sup>`). 습관적으로 적용한다.
- 수식은 **유니코드 문자 + `<sup>`/`<sub>` 까지만**. 그 외 태그는 escape 되어 그대로 보인다.
- 기본 CONFIG(각 파일에 들어 있는 완성 예제)의 구조를 그대로 따라 쓰면 안전하다.
- CONFIG가 잘못되면 백지가 아니라 **오류 카드**가 뜬다 — 메시지를 읽고 그 필드만 고친다.

**공통 필수 필드** (4종 동일): `schemaVersion`(=1) · `template` · `title` · `theme` · `credit`
`subtitle` 은 선택.
`theme` 은 `indigo` `pink` `green` `violet` `teal` `amber` 6종 중 하나.
`credit` 은 `{ "mode": "anonymous", "name": "", "school": "" }` 가 기본(무기명).
선생님이 원하시면 `{ "mode": "named", "name": "홍길동", "school": "○○중학교" }`.

**쉘별 추가 필드**

| 쉘 | 추가 필드 | 의미 규칙(생성 전 스스로 검사) |
|---|---|---|
| quiz | `shuffle`(선택, `{"questions":bool,"choices":bool}`) · `questions[]`(1개 이상) | 아래 문항 3종 참고 |
| speed | `timeLimitSec`(양수) · `speedup`(boolean) · `left.label` · `right.label` · `cards[]`(2장 이상, `{"text","side":"left"\|"right"}`) | 두 범주는 **상호배타** — 모든 카드가 정확히 한쪽에만 속하는지 확인 |
| pair | `pairs[]`(3짝 이상, `["왼쪽","오른쪽"]`) | **왼쪽 값끼리 전부 다르고, 오른쪽 값끼리도 전부 달라야** 한다 |
| order | `prompt`(배열 지시문) · `items[]`(3개 이상, **정답 순서 앞→뒤**) | 빈 문자열·중복 금지. 순서가 **유일**해야 한다(동점 금지) |
| graph | `questions[]`(1개 이상) — 아래 문항 2종 | 그래프는 **계수만 적으면 엔진이 그린다**. 보기끼리 **같은 그래프가 겹치면 안 된다** |

graph 문항 2종 (함수 객체 = `{"type":"linear","a":수,"b":수}` · `{"type":"quadratic","a":수,"p":수,"q":수}`(y=a(x−p)²+q, a≠0) · `{"type":"inverse","k":수}`(y=k/x, k≠0)):

- `{"mode":"toGraph","prompt":…,"answer":{함수},"distractors":[{함수},…2~3개],"explanation":…}`
  — 정답 1개와 오답들을 섞어 작은 그래프 4개로 보여준다. **오답은 정답과 계수가 달라야** 한다
  (부호만 다르게·절편만 다르게처럼 흔한 오개념을 노리면 좋다).
- `{"mode":"toEquation","prompt":…,"graph":{함수},"choices":["y = -x + 2",…],"answerIndex":정수,"explanation":…}`
  — 그래프를 크게 보여주고 식을 4지선다로 고른다.

quiz 문항 3종:

- `{"type":"choice","prompt":…,"choices":[…],"answerIndex":정수,"feedbacks":[…],"explanation":…}`
  — `feedbacks` 는 **필수**이며 `choices` 와 **길이가 같아야** 하고, 오답 선택 시 표시된다(`""` 면 `explanation` 으로 대체).
  `answerIndex` 는 `choices` 범위 안의 인덱스.
- `{"type":"short","prompt":…,"answer":"…","aliases":[…],"explanation":…}` — `aliases` 는 함께 인정할 표현.
- `{"type":"ox","prompt":…,"answer":true/false,"explanation":…}` — `answer` 는 boolean(true=○).

쉘 조작 방식(선생님께 설명할 때 이대로 말한다):

- **pair** — 카드가 **처음부터 모두 보인다**(뒤집기 없음). 짝이 되는 둘을 눌러 고른다.
  기억력 게임이 아니라 판단하는 활동이다.
- **order** — `<보기>`의 카드를 눌러 **번호가 붙은 빈 칸에 채운다**(드래그 아님).
  채운 카드를 다시 누르면 보기로 돌아간다. 전부 채우면 [확인].

## 자유 생성 경로 — 가드레일 (쉘로 안 될 때만)

결정표 다섯째 줄에 해당할 때만 진입한다. 진입 전 반드시:

> `[🎤 진행자]` 결정표에 없는 형태 → 자유 생성으로 갑니다. **1~2분 추가 소요 가능**.

지킬 것 7가지:

1. **단일 `index.html`** — CSS·JS 전부 인라인.
2. **외부 리소스·네트워크 요청 0** — `http(s)` URL 참조, `fetch`/XHR/WebSocket,
   외부 `src`/`href` 전부 금지.
3. **모바일 우선** — 세로 화면 기준, 터치 타깃 **44px 이상**.
4. **텍스트는 escape** 해서 렌더링. 수식은 **유니코드 + `<sup>`/`<sub>`** 수준으로 쓰고,
   꼭 필요할 때만 **MathML Core** 한정으로 쓴다.
5. **크레딧 기본 익명** — 푸터에 "2026 과학·수학·정보 교사 컨퍼런스에서 제작"
   (선생님이 원하시면 성함·학교 표기).
6. **학교급 어휘 준수** — 초등에게 중등 용어를 쓰지 않는다. 단원명은 **2022 개정 교육과정 영역명** 기준.
7. **시간 초과 조짐이 보이면** `[🎤 진행자]` 큐를 주고 **쉘 경로로 유도**한다
   (선생님께는 "비슷한 형태를 30초 안에 만들 수 있어요. 그쪽으로 갈까요?" 라고만 여쭌다).

검증 2단은 자유 생성에서도 동일하게 적용한다.

## ④막 — 배포 (~2분)

### ④-1. README.md 생성

`workspace/<이름>/README.md` 를 만든다. **쉘·템플릿 이야기는 한 줄도 넣지 않는다**
(단, 리믹스용 프롬프트의 "CONFIG 부분" 문구는 스펙 원문이므로 그대로 둔다) —
집에서 웹 채팅만으로 **처음부터** 만들 수 있는 완결 프롬프트여야 한다.

사용자명·저장소명을 아직 못 받았으면 체험 주소 줄은
`(리포를 만든 뒤 https://<사용자명>.github.io/<저장소명>/ 형태로 바꿔 적으세요)` 로 적고,
받으면 **업로드 안내 전에** 실제 값으로 갱신한다 — 플레이스홀더가 남은 채 업로드시키지 않는다.

````markdown
# <작품 제목>

<한 줄 소개>

- **체험 주소**: https://<사용자명>.github.io/<저장소명>/
- **대상**: <학교급·학년> · <단원(2022 개정 교육과정 영역명)>
- **학습목표**: <한 줄>
- **만든 날**: <YYYY-MM-DD> · 2026 과학·수학·정보 교사 컨퍼런스 · 서울시교육청 수학 부스

### 2) 처음부터 만들기용

ChatGPT/Claude 웹 새 채팅에 붙여넣으면 오늘과 **같은 구조의** 자료를 만들 수 있습니다.
````

### ④-4. QR 출력 → 폰 스캔

③-1에서 받은 **사용자명·저장소명이 확정된 뒤에만** 출력한다. 아직 못 받았으면 진행자에게
확인부터 한다 — `<사용자명>` 플레이스홀더가 남은 채로 QR을 만들지 않는다.

```bash
npx qrcode --small "https://<사용자명>.github.io/<저장소명>/"
```

폰으로 스캔하시게 안내한다. 빌드가 늦으면 **"잠시 후 열려요"** 로 마무리해도 된다
(다음 손님 응대와 겹쳐도 무방).

**실패·시간 부족 시**: 파일은 `workspace/<이름>/` 에 그대로 보존된다.
README의 「집에서 이어하기」 + 유인물로 안내하고 마무리한다.

## Claude 응답 지연·장애 시 분기

생성이 막히면 **쉘의 기본 CONFIG(=완성 예제)를 그대로 두고 시연·완성**한다.
템플릿을 복사만 하면 바로 작동하는 완성작이 된다.

| 쉘 | 기본 CONFIG 내용 |
|---|---|
| quiz | 정비례 형성평가 (choice·short·ox 혼합) |
| speed | 유리수 vs 무리수 분류 |
| pair | 인수분해 짝맞추기 |
| order | 작은 수부터 차례로 배열 |
| graph | 식과 그래프 연결하기 (일차·이차·반비례) |

선생님께는 이렇게 말한다 — "지금은 준비된 예시로 배포까지 먼저 해볼게요.
**기획 카드가 오늘의 핵심**이라, 집에서 그대로 쓰시면 똑같이 만들어집니다."
②막 기획 카드와 README 프롬프트는 **원래 대화 내용 그대로** 만들어 드린다(체험의 알맹이는 유지).

**세션 도중 재시작한 경우**(Claude Code가 종료됐다 다시 `/booth` 로 들어옴): 진행자가
"이어서"라고 알려주면 **새 폴더를 만들지 말고** 기존 `workspace/<이름>/` 내용을 확인해
이미 끝난 막은 건너뛰고 남은 막부터 이어간다.
